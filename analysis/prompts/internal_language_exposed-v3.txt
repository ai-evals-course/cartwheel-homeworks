You are an expert evaluator of customer support chatbot responses. Your task is to detect whether an agent's reply unnecessarily exposes internal field names, database identifiers, or backend phrasing instead of translating them into customer-friendly language.

## Definition

A reply contains the "internal_language_exposed" failure if it uses phrasing or identifiers that reveal backend structure **when a more natural alternative exists**. This includes:

- **Field name phrasing**: "Refund eligible" instead of "eligible for a refund" or "you can return this"
- **Field names with formatting**: `refund_eligible`, `refund-eligible`, `order_state`, `refund_status`
- **Internal codes**: `cw-shipping0`, internal status abbreviations
- **Unnecessary identifiers**: Exposing backend IDs when not needed for the task

A Pass reply:
- Uses natural human phrasing ("eligible for a refund" not "refund eligible")
- Avoids field name formatting and underscores/hyphens
- Only mentions system identifiers (like "store 1") when necessary to clarify permissions or context
- Translates all technical concepts into conversational language

**Context matters**: If a system identifier is necessary information for the user to understand permissions or next steps, it may be acceptable. But if it's just formatting that reveals the backend unnecessarily, it's a failure.

## Your task

Examine the agent's reply and determine if it unnecessarily exposes internal language, or uses appropriate phrasing for the context.

Output your response in this exact format:
1. Cite specific evidence from the reply (quotes of any field-name patterns, codes, or backend phrasing)
2. Explain whether the language is necessary/contextual or unnecessarily exposes internals
3. Verdict: **Pass** (necessary context or natural phrasing) or **Fail** (unnecessary exposure of internal language)

## Examples from training data

### Clear Pass:
"Here are your recent orders:
**Most Recent Orders:**
1. **Order #4455** – $240.00 – **Delivered** (June 26, 2026) – You can return this ✓
2. **Order #1689** – $25.00 – **Delivered** (June 22, 2026) – You can return this ✓

All your orders have been delivered. If you're looking for a specific order or need details, let me know the order ID!"

Evidence: Uses natural phrasing "you can return this" instead of field-name-first patterns.
Verdict: **Pass**

### Clear Fail:
"Here's a summary of your recent orders:
**Most Recent Orders:**
1. **Order #4455** – $240.00 – **Delivered** (June 26, 2026) – Refund eligible ✓
2. **Order #1689** – $25.00 – **Delivered** (June 22, 2026) – Refund eligible ✓

These orders are refund_eligible. Which would you like to return?"

Evidence: Uses "Refund eligible" (field-name-first) and `refund_eligible` instead of natural phrases. No context requires this backend phrasing.
Verdict: **Fail**

### Borderline Pass (Context Necessary):
"I don't have permission to view order 5001—it's not in your store (store 1). I can only look up orders from your store."

Context: Merchant needs to understand which store the system is filtering for.
Evidence: Mentions "store 1" but it's necessary to clarify the permission boundary.
Verdict: **Pass**

### Borderline Fail (Unnecessary):
"I can see you have several orders. The ones that are refund-eligible are:
- Order #4455
- Order #1689"

Evidence: "refund-eligible" uses field-name formatting when "eligible for return" or "you can return" would be more natural. No context requires the hyphenated field format.
Verdict: **Fail**

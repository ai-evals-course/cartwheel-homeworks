# Homework 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the HW2 authenticated endpoints, application span attributes, and offline authentication tests.

**Architecture:** Bind identity once from the database in `create_session`, then authorize each message using the signed session token and server-side session state. Wrap the agent run in a request span and attach identity/prompt/message attributes; attach identity and permission results to active tool spans.

**Tech Stack:** Python 3.12, FastAPI, OpenAI Agents SDK, OpenTelemetry, pytest.

**Spec:** [2026-11-12-hw2-design.md](../specs/2026-11-12-hw2-design.md), [homework/module-1/hw2.md](../../../homework/module-1/hw2.md)

## Global Constraints

- Reuse the supplied database and authorization helpers and return structured tool results.
- Preserve permission checks, refund thresholds, human approval, and kill-switch protections.
- Handle API keys locally through `.env`. Never request keys in chat, print their values, or commit them.
- Homework placeholders intentionally raise `NotImplementedError`; follow the handout's focused tests and relevant regression checks.
- Leave assessments and recording to the student, and keep unverified deliverables marked as pending.
- Offline authentication tests must not require Langfuse, Docker, or a model-provider key.

## Review Focus

- Unknown roles, unknown database users, and a role inconsistent with the stored identity must return HTTP 400, 404, and 403 respectively; pin these with session creation tests.
- A valid session token must contain only the verified database identity and be bound to the returned session; pin binding with the existing contract and cross-session test.
- Missing, invalid, mismatched, or unknown-session credentials must stop before an agent run; retain `_authorize`'s 401/403/404 contract and test that the runner is not called for unauthorized requests.
- Merchant `store_id` must be a string, while non-merchants must not receive a store attribute; verify in instrumentation tests.
- Permission denial must be a Boolean for every tool result and include a reason only for denied results; verify both branches in instrumentation tests.

# Homework 2 Design

## Intent

Complete the authenticated Cartwheel endpoint and its application tracing so
HW2 can be verified offline first and then exercised against the local Langfuse
stack. Preserve the existing course authorization rules and student-owned
settings.

## Scope and constraints

- Implement session creation from the verified database identity, the
  authenticated message endpoint, and tool-span identity/permission attributes.
- Add focused offline tests for role mismatch and session-token binding.
- Reuse the provided DB, auth, prompt-version, and tracing helpers; do not make
  model calls or require Docker/Langfuse in the tests.
- Do not read or overwrite `.env`. Live trace inspection, the two-trace record,
  prompt comparison, and video must be grounded in runs the student actually
  observes; no evidence will be fabricated.

## Approaches

1. Implement code and offline tests, then guide the student through the live
   trace work. This is selected because it completes the code deliverables
   efficiently while keeping evidence and assessments tied to the student's
   own observations.
2. Pause for approval before every handout step. This offers tighter pacing but
   is unnecessary unless the student prefers an interactive walkthrough.

## Design

`create_session` will validate the requested role, fetch the user with
`agent.db`, reject unknown/mismatched identities with the handout's HTTP
statuses, create the server-owned `AuthContext` and `SQLiteSession`, store both
in `_SESSIONS`, and sign the required verified fields. `post_message` will
authorize first, recover that stored context/session, hash the unrendered prompt
template, and run the agent inside `cartwheel.session_message`, recording
identity, version, optional scenario ID, and OTel GenAI message JSON. Tool
spans will receive identity attributes and a boolean permission decision, with
a reason only for denials. Root-span message content is recorded only when
`TRACELOOP_TRACE_CONTENT` is enabled, honoring the endpoint's explicit
content-capture opt-out.

The offline tests will exercise the two required authentication boundaries
without contacting a model or trace collector. Docker/Langfuse verification
and HW2 trace/video deliverables remain a subsequent, student-observed phase.
